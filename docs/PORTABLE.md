# Two versions of the app

| | development version | portable version "AoE2HDBeta" |
|---|---|---|
| package | `dev.j3rry.villagebuilder` | `co.domotix.ao2hdbeta` |
| export preset | `Android` | `Android portable` (excludes `assets/aoe/*`) |
| game files | bundled in the APK (~137 MB) | none (~29 MB); imported on first start from the player's own copy |
| build and install | `tools/tablet.sh` (or `tools/tablet.sh dev`) | `tools/tablet.sh portable` |
| data location | `res://assets/aoe/` | `user://gamedata/` (app-private, same layout) |

Both builds run the same code. `GameData` (scripts/game_data.gd) finds the data: the bundled folder if it exists, otherwise a finished
import (`user://gamedata/.complete`). `scenes/boot.tscn` is the main scene: it starts the game at once when there is data, otherwise it
shows the import wizard (`SetupWizard`). Tests can use the import with `AOE_DATA=imported`.

## The import (scripts/importer/)

Runs in a thread, in stages recorded in `user://gamedata/progress.json` so it can be paused, stopped and resumed (units: every 20 sprites).

| stage | what | port of |
|---|---|---|
| rules | inflate the .dat (`inflate.gd`), read it (`dat_reader.gd`, layout from `data/dat_schema.json`), names from `language*.dll` (`pe_strings.gd`), `rules.json`, `graphics.json` (`rules_builder.gd`) | tools/import_dat.py |
| base | hand-picked sprites, `manifest.json` (`base_sprites.gd`) | tools/extract_aoe_godot.py |
| units | one task per unit/building, `units.json` (`unit_extract.gd`) | tools/extract_units.py |
| terrain | tiles, blend masks, overlays, `terrain.json` (`terrain_extract.gd`) | tools/extract_terrain.py |
| sounds | effects (wav) and the first 6 MB of two music tracks (`sound_extract.gd`) | extract_sounds |

`data/dat_schema.json` is generated by `tools/make_dat_schema.py` from openage's structure definitions (GPLv3, see that file); it holds no game data.

Needed from the game folder (about 190 MB): `Data/empires2_x1_p1.dat`, `graphics.drs`, `interfac.drs`, `terrain.drs`, `sounds.drs`, `sounds_x1.drs`,
`blendomatic_x1.dat`, `pal_2.pal`, `pal_4.pal`, `Data/Slp/foak_nn.slp`, `fpin_nn.slp`, `Bin/en/language.dll` (and, optional, `language_x1.dll`,
`language_x1_p1.dll`, `Sound/music/music1.mp3`, `xmusic1.mp3`).

## Checking the port

Every stage was compared with the Python tools' output: rules.json/graphics.json/units.json/terrain.json/manifest.json are identical, sounds and
music are byte-identical, PNGs are pixel-identical except for a rounding step of at most 1-2 levels where sprites are alpha-blended (the Python
tools' palette PNGs are slightly lossy, the import writes exact RGBA). On a PC the whole import takes about 35 s.

Tests: `tests/inflate`, `dat`, `rulesbuild`, `extract` (STAGE=base|units|terrain|sound, compare with `tools/*.py` output), `importer`
(`MODE=resume` also tests pause, cancel and resume), `wizard`.

## Not done yet

- The import stops when Android kills the app; it resumes, but does not run in the background (that needs an Android foreground service).
